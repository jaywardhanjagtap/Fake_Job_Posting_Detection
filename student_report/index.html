Fake Job Posting Detection

Machine Learning Project Report

Using TF-IDF text vectorization and classification models to detect fraudulent job postings

1. Project Overview

This project uses machine learning to identify fraudulent job postings by analyzing both the text content (job description, requirements, company profile) and structured metadata (employment type, required experience, etc.) of each posting. The dataset used is the EMSCAD "Real or Fake Job Posting" dataset.

2. Data Cleaning

Several columns had a large amount of missing data. The chart below shows the percentage of missing values for each column.

Based on this, the following cleaning steps were applied:

  • salary_range was dropped entirely (84% missing - too sparse to be useful)
  • Missing text fields (description, requirements, benefits, company_profile) were filled with empty strings
  • Missing categorical fields (department, industry, etc.) were filled with the label "Unknown"

4. Structured Features

Besides text, a few simple yes/no fields turned out to be strong indicators of fraud:

  • Postings without a company logo had a 15.9% fraud rate, vs only 2.0% for postings with one (about 8x higher)
  • Postings without screening questions had a 6.8% fraud rate, vs 2.8% for postings with questions
  • Postings offering remote work had a higher fraud rate (8.3%) than non-remote postings (4.7%)

5. Model Comparison

Two classification models were trained on the combined text (TF-IDF) and structured features: Logistic Regression and Naive Bayes.

Model Accuracy Precision Recall F1-Score
Logistic Regression 0.963 0.574 0.902 0.701
Naive Bayes 0.958 0.592 0.428 0.497
Why Logistic Regression won: It caught about 90% of fraudulent postings (recall), compared to only 43% for Naive Bayes. For fraud detection, missing real fraud cases is usually worse than a few false alarms, so the higher recall makes Logistic Regression the better choice here.

Confusion Matrix (Logistic Regression)

  • 156 out of 173 fraudulent postings were correctly identified
  • 116 real postings were incorrectly flagged as fraud (false positives)
  • 17 fraudulent postings were missed (false negatives)

6. Does Text Cleaning Actually Help?

To test whether manually cleaning the text (removing punctuation, HTML, lowercasing) actually improved results, the same model was also trained on the raw, uncleaned text.

Finding: Surprisingly, the uncleaned text performed slightly better (F1 = 0.709 vs 0.701). This is likely because TF-IDF already lowercases text and removes common stop words automatically, so our manual cleaning step didn't add much extra value. This shows that preprocessing assumptions should be tested rather than assumed.

8. Limitations

  • Class imbalance: Only 4.8% of postings are fraudulent, so even with balanced class weighting, the model still produces some false positives. In a real system, flagged postings should go to human review rather than being auto-rejected.
  • Vocabulary can change over time: The TF-IDF vocabulary is fixed based on training data. Scam language evolves, so the model would need retraining on new data periodically.
  • Structured features can be faked: A scammer could easily add a logo or screening questions to avoid detection, since these are easy to fake.
  • English-only: The model was trained only on English text and may not work well on postings in other languages.

9. Summary

This project built a fraud detection system for job postings by combining TF-IDF text features with structured metadata. Logistic Regression outperformed Naive Bayes, mainly due to better recall. Simple structural signals (especially having a company logo) turned out to be strong predictors on their own. Text cleaning did not meaningfully improve results in this case, showing the importance of testing preprocessing choices rather than assuming they help. Overall, the model performs well at catching fraudulent postings, though it should be used to assist human reviewers rather than to automatically reject postings.
